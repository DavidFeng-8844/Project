\section{SaaS Platform Architecture}
\label{sec:saas_architecture}

To transition the deep learning models into an industrial service, a Software-as-a-Service (SaaS) platform was developed. The design strictly prioritises decoupling, multi-user concurrency, and data security.

\subsection{Architecture Overview and Data Isolation}
The system adopts a decoupled four-tier architecture (Figure \ref{fig:saas_architecture}), isolating presentation, routing (Flask), execution (\texttt{ThreadPoolExecutor}), and relational persistence (SQLAlchemy).

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.7\textwidth]{figures/saas_four_tier_architecture.png}
    \caption{Four-tier SaaS architecture.}
    \label{fig:saas_architecture}
\end{figure}

To accommodate multiple power grid subsidiaries, strict Entity-Relationship boundaries apply. Every \texttt{InferenceTask} inherits both a \texttt{user\_id} and a \texttt{tenant\_id}. Security is enforced at the routing layer via interceptors, appending \texttt{tenant\_id} filters to all queries rather than relying on implicit ORM hooks. 

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.6\textwidth]{figures/saas_er_diagram.png}
    \caption{Data isolation constraints.}
    \label{fig:saas_er}
\end{figure}

\subsection{Asynchronous Execution and Model Registry}
Synchronous inference mechanisms exhaust Web frameworks under concurrent load. Ergo, an event-driven task pipeline (\texttt{PENDING} $\rightarrow$ \texttt{RUNNING} $\rightarrow$ \texttt{SUCCESS}) was designed. Client submissions immediately return HTTP 202, while memory queues instantaneously awaken background worker threads, eliminating database polling bottlenecks.

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.65\textwidth]{figures/saas_dataflow_diagram.png}
    \caption{Event-driven asynchronous lifecycle.}
    \label{fig:async_dataflow}
\end{figure}

Additionally, to prevent 12 GB hardware resource exhaustion from simultaneously loading YOLOv8s and Mask R-CNN, an Adapter Pattern Model Registry defers memory allocation. Weights are exclusively \textit{lazy-loaded} upon their first explicit invocation and cached thereafter.
